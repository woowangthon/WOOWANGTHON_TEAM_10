## 3. 구현할 때 지킬 보안 규칙

1. **API 키는 저장소에 절대 넣지 않는다.** 로컬에서는 `.env.local`(커밋되지 않음), 배포 환경에서는 Vercel의 Environment Variables에 넣는다. 채팅창에도 붙여넣지 않는다.
2. `NEXT_PUBLIC_`으로 시작하는 변수는 브라우저에 그대로 노출된다. Anthropic 키, DB 주소, Supabase service role 키는 이 이름으로 만들지 않는다.
3. LLM 호출과 DB 쓰기는 **서버 코드에서만** 한다. 브라우저 코드에서는 하지 않는다.
4. 패키지는 널리 쓰이는 공식 패키지만 설치하고, `package-lock.json`을 커밋하고, `npm audit`을 확인한다. 이름이 비슷한 가짜 패키지에 주의한다.
5. 권한 검사, 팀 경계, 근거 ID 검증, 철회 반영에는 자동 테스트를 둔다(구체화 문서 §9).
6. 시연·평가 데이터는 가상 메모만 쓴다. 실제 개인정보나 킥오프 전사 원문은 넣지 않는다.
7. 공개 전환 직전에 전체 커밋 기록을 다시 한 번 비밀정보 검사한다.

## 5. 변경 기록과 2단계(AI 연결 지점) 보안 설계 — 2026-11-02 추가

### 계획에서 바뀐 점
- 로그인은 Supabase Auth 대신 **직접 구현**했다(Node 내장 `crypto`의 scrypt 해시와 HMAC 서명 쿠키). 외부 계정·키 없이 시연할 수 있다. 데이터베이스는 어느 PostgreSQL이든 쓸 수 있다.
- 로그인 시도 제한은 서버 메모리 기준이라 서버가 재시작되면 초기화된다. 대회 시연 규모에서 감수하는 한계다.

### 바꾸지 않았고 남아 있는 한계

- **세션 즉시 취소 불가**: 로그아웃은 브라우저 쿠키만 지운다. 비밀번호 변경·강제 로그아웃 기능이 없다. 필요하면 세션 표를 추가해야 한다.
- **요청 제한은 서버 메모리 기준**: Vercel 처럼 서버 인스턴스가 여러 개면 인스턴스마다 따로 센다. 대회 규모에서는 감수한다.
- **CSP 가 `'unsafe-inline'` 스크립트를 허용**: Next.js 의 인라인 스크립트 때문이다. 주입 공격 방어는 React 의 자동 이스케이프에 의존한다. nonce 방식은 모든 페이지를 동적 렌더링으로 바꿔야 해서 보류했다.
- **운영자(DB 접근 권한자)는 모든 원문을 볼 수 있다**: 암호화하지 않는다. 팀원에게 이 사실을 알려야 한다.
- **메모의 "AI 정리 허용" 은 만든 뒤 바꿀 수 없다**: 바꾸려면 삭제 후 다시 작성해야 한다. → 11/7: 공유한 지식은 「AI 참고」를 언제든 끄고 켤 수 있게 바꿨다(§9).

## 7. 실제 AI(OpenAI) 연결 점검 — 2026-11-04

| 항목 | 확인한 사실 | 대응 |
| --- | --- | --- |
| 키 보관 | 이 클라우드 환경은 키를 컨테이너 환경변수가 아니라 **프록시에서 주입**한다. 컨테이너 안 코드·로그·채팅 어디에도 키가 없다 (`OPENAI_API_KEY` 길이 0 확인) | 제공자는 키가 없으면 `Authorization` 헤더를 아예 보내지 않도록 구현. 본인 PC·Vercel 에서는 환경변수의 키를 쓴다 |

- `db/migrations/003_account_deletion.sql` 은 코드가 빠뜨린 참조가 있어도 외래키 오류로 막히지 않게 하는 안전망이다. `notes.author_id` 만 일부러 남겨, 메모는 반드시 조언 본문 제거와 함께 코드로 지우게 했다.

### 남아 있는 한계

- **Neon 의 백업·기록 보존**: 지운 행도 Neon 의 시점 복구(무료 요금제 기본 수 시간~1일) 동안은 백업에 남는다. 안내 문구에 따로 적지 않았다.
- **Vercel 요청 로그**: 서버 로그에 본문·이메일은 남기지 않지만 접속 IP·경로는 Vercel 이 보관한다.
- **이전 smoke 시험 계정**: 이번 변경 전에 배포 점검으로 만든 `smoke+…@example.invalid` 계정은 아래 SQL 로 한 번 지운다(Neon SQL Editor). 메모·조언까지 함께 지우려면 각 계정으로 로그인해 탈퇴하는 편이 정확하지만, 시험 자료뿐이므로 아래로 충분하다.

```sql
-- smoke 시험 계정과 그 자료 정리 (003 마이그레이션 적용 후)
begin;
delete from notes where author_id in (select id from users where email like 'smoke+%@example.invalid');
delete from teams t
where exists (select 1 from memberships m join users u on u.id = m.user_id
              where m.team_id = t.id and u.email like 'smoke+%@example.invalid')
  and not exists (select 1 from memberships m join users u on u.id = m.user_id
                  where m.team_id = t.id and m.status = 'active' and u.email not like 'smoke+%@example.invalid');
delete from users where email like 'smoke+%@example.invalid';
commit;
```


## 9. 대화형 개편과 출처 비노출 — 2026-11-07

사용자 요청으로 화면을 "일반 AI 대화"로 바꿨다. **출처를 드러내지 않는 것이 제품의 핵심**이라는 결정에 따라, 화면·답변 문장·서비스 동작 어디에서도 "팀 메모를 참고했다"는 신호가 나오지 않게 했다. 동시에 권한·개인정보 규칙은 그대로 지킨다.

### 출처 비노출 규칙

| 층 | 규칙 | 구현 |
| --- | --- | --- |
| 답변 문장 | 지시문으로 출처 표현("메모", "공유된 내용", "기록에 따르면", "팀원이 남긴", 번호 등)을 금지. 서버가 다시 검사해 나오면 **한 번 다시 쓰게** 하고, 그래도 남으면 그 문장을 뺀다. 질문 자체에 그 낱말이 있으면(예: "메모 앱 추천") 검사하지 않는다 | `validate-output.ts` `sourceLeaks`·`dropLeakySentences`, `chat.ts` `generate` |
| 화면 | 근거·출처를 보여주지 않는다. 답변이 기댄 지식이 철회·수정·삭제되거나 AI 참고에서 빠져도 **'숨김' 안내를 띄우지 않고**, 다음에 대화를 열 때 같은 질문으로 답변을 조용히 다시 쓴다. 그동안은 평범한 "답변 작성 중…"으로 보인다 | `chat.ts` `refreshStale`, `/api/tasks/:id/chat/refresh` |
| 모델에 주는 것 | "그 내용은 쓰지 마"라고 말하지 않는다(그 내용을 다시 보내야 하고, 모델이 "반영하지 않을게요"라고 말해 출처가 드러난다). 대신 **아예 보내지 않는다**: 빠진 지식은 지식 목록에서 빠지고, 그 지식이 넘어갔던 이전 턴은 이어지는 대화에 질문만 넣는다(답변 제외). 모델이 반영 사실을 밝히지 않았어도 그 내용이 다시 흘러들지 않는다 | `chat.ts` `historyFor` |
| 작성자 | 모델에 작성자 이름·이메일·ID를 주지 않는다 | 테스트로 확인 |

### 권한·개인정보 규칙

| 항목 | 규칙 |
| --- | --- |
| 개인 메모 | '메모하기'로 쓴 메모(`notes.origin='memo'`)는 작성자만 본다. 정리 없이 바로 공유하는 경로는 없다 |
| AI 정리 | 작성자가 고른 **자기 메모만** 모델에 간다. 결과는 저장하지 않고, 작성자가 고쳐 공유할 때 그 문장 그대로 저장 |
| AI 참고 | 공유할 때 고르고, **공유 후에도 끄고 켤 수 있다**. 끄면 그 지식은 모델에 가지 않고, 그 지식을 반영한 답변은 조용히 다시 쓰인다 |
| 삭제 | 지식을 삭제하면 그 지식을 반영한 답변 본문을 **즉시** DB 에서 지우고(다시 쓰기 전에), 다시 열 때 새로 쓴다. 다시 쓰기에 실패해도 예전 내용은 되살아나지 않는다 |
| 대화 공개 범위 | 묻는 사람에게만 보인다(같은 팀원도 못 봄) |
| 다시 쓰기 중복 | 같은 답변을 두 곳에서 동시에 다시 쓰지 않도록 상태를 원자적으로 바꾼 쪽만 진행. `started_at` 으로 오래된 요청이 '멈춘 요청'으로 오인되지 않게 함 |

### 남는 한계

- 모델이 지식을 쓰고도 반영했다고 밝히지 않은 **과거 답변의 본문**은, 그 지식을 삭제해도 질문한 사람의 화면·DB 에 남는다. 앞으로의 대화에는 흘러들지 않는다(질문만 넘김). 이 본문까지 지우려면 "지식이 넘어간 모든 답변을 다시 쓰기"로 바꾸면 되지만, 작은 팀은 매번 공유 지식 전부를 넘기므로 지식 하나를 바꿀 때마다 모든 대화가 다시 쓰인다.
- 다시 쓴 답변은 이전 답변과 표현이 다를 수 있다.
- 출처 표현 검사는 낱말 목록 기반이다. 목록에 없는 우회 표현은 지시문과 평가로 관리한다(실제 모델 30회에서 최종 답변의 출처 표현 0건, `docs/평가_보고서.md` §13).

시험: `tests/chat.test.ts` (16개), 배포 점검(`npm run smoke`)의 "공유 철회 → 대화 답변은 사유 표시 없이 다시 쓰임".

## 15. Bear 방식 UI 개선 — 2026-11-10

기준은 GitHub main `3087d9c`이다. 별도 검토본의 실제 화면과 검사 결과를 사용자에게 보여 준 뒤 저장소 반영 승인을 받아 적용했다. 변경은 UI 파일 8개와 날짜별 변경 기록에 한정한다. 로컬 미리보기용 설정·환경 파일·가상 계정은 포함하지 않는다. 운영 배포의 완료 여부는 이 기록과 별도로 확인한다.

- 공통 탐색 / 기록 목록 / 본문 3열로 구성하고 휴대폰에서는 목록을 접어 본문을 읽는다. 로그인·팀 목록·프로젝트 대화·메모·회의록과 메모 창을 같은 스타일로 맞췄다.

- 메모의 저장 전 수정은 이동 확인으로 보호하고, 회의록 작성·수정 중에는 목록 이동을 막는다. 목록 선택 시 모바일 목록을 닫고 본문 제목으로 포커스를 옮긴다. 메모 창은 Tab 순환·Escape·원래 버튼 포커스 복귀를 지원한다.
- 브라우저 검증에서 기존 `history.replaceState(null, ...)`가 Next 탐색 상태를 지우고 개발 중 반복 로드를 유발함을 재현했다. 주소 변경은 Next 라우터에 맡기고 프로젝트 항목은 실제 링크로 연결해 탐색 상태를 보존했다. 검토본은 별도 브라우저 우회 없이 안정적으로 열린다.
- `src/lib`, API, 마이그레이션, 테스트, 평가 자료와 패키지/잠금 파일은 기준본과 해시가 같다. 프롬프트 버전도 바꾸지 않았다.

검증 DB는 운영과 분리된 로컬 PostgreSQL이다. 최초 Windows `C` locale에서 한글 trigram이 비어 검색 관련 테스트 20개가 실패했으며, 앱·테스트를 수정하지 않고 로컬 DB를 `Korean_Korea.utf8`로 보완해 전부 통과했다. 미리보기 자료는 가상이고 실제 OpenAI 호출·운영 DB 변경·모델 평가는 하지 않았다.

대화 화면 추가 브라우저 점검 12개도 통과했다. 직접 주소 열기, 공개 출처의 비노출 규칙, 320~1440px 가로 넘침, 화면 테마 유지, 예시 질문의 입력만 채우기, 중복 전송 방지, 두 계정의 대화 분리를 확인했다. 대기 표시는 요청을 서버로 보내기 전에 지연·중단하는 네트워크 모의로 확인했으며 실제 모델 속도를 측정한 결과가 아니다. 예시 질문의 장식 화살표는 접근성 이름에서 제외했다.

승인본을 실제 저장소 작업 브랜치에 반영한 뒤에도 전용 테스트 DB에서 npm run check(15파일·144테스트)와 npm run build를 실행해 둘 다 종료 코드 0을 확인했다. 운영 DB나 실제 AI는 사용하지 않았다.

### 보안 검토

- **공개 응답**: `/api/health`가 새로 알려 주는 것은 빠진 마이그레이션의 개수와 배포 커밋 앞 7자다. 빠진 파일 이름은 서버 로그에만 남긴다. 커밋은 저장소의 커밋이라 비밀이 아니고, 제출한 커밋과 배포본이 같은지 확인하는 데 쓴다.
- **로그**: 오류 메시지·SQL·본문은 여전히 남기지 않는다. 추가한 것은 다섯 글자 오류 코드뿐이고, 그 형식이 아니면 남기지 않는다.

- **배포 확인이 운영에 보내는 요청**: 상태 점검, 코드 미리 받기(DB에 쓰지 않음), 실패하는 로그인 두 번, 로그인 없는 내 정보 조회. 계정이나 자료를 만들지 않는다. 받은 코드와 발급권은 쓰지 않고 버리며 출력하지 않는다.

### 보안·권한 검토

- **다시 답하기의 권한**: 대화는 묻는 사람에게만 보인다는 규칙 그대로다. 남의 질문을 다시 시도하면 404이고, 다른 프로젝트의 질문은 다시 답하지 않는다. 같은 대화 API를 쓰므로 사용자당 시간당 호출 제한도 그대로 적용된다.
- **중복 호출 방지**: 실패 상태를 처리 중으로 바꾸는 갱신 한 번으로 권리를 잡는다. 동시에 두 번 눌러도 모델은 한 번만 부른다. 처리 중이거나 이미 답한 질문은 다시 부르지 않는다.
- **다시 답할 때 넘기는 대화**: 마지막 질문이면 새 질문과 같게, 뒤에 다른 질문이 이어졌다면 그 질문 시점까지의 대화만 넘긴다. 지식이 바뀐 답변을 다시 쓰는 기존 규칙(§9)과 같은 방식이다. 지식의 권한·상태 필터, 입력 기록, 출처 검사는 바뀌지 않았다.
- **취소**: 취소된 요청은 실패로 끝나고 결과를 저장하지 않는다. 호출자가 받는 오류(시간 초과)는 이전과 같다.
- 프롬프트, 공개 범위, 「AI만 참고」 규칙, 비노출 문구는 바꾸지 않았다. 다시 답하는 동안의 대기 문구도 기존과 같다.

### 보안·권한 검토

- **나간 사람의 철회·삭제**: 대상은 자기가 쓴 메모뿐이고, 남의 메모와 회의록은 404 그대로다. 나간 사람이 팀 자료를 읽는 경로는 열지 않았다(조회는 여전히 현재 팀원만).
- **자동 철회**: 삭제가 아니라 철회다. 내용은 작성자 계정에 남고, 다시 참여하면 다시 공유할 수 있다. 팀에 공개한 메모를 남기는 사전 합의(원안 §8.1)는 바꾸지 않았다.
- **탈퇴 시 팀 삭제**: 기준은 이전과 같다(활동 중인 팀원이 없는 팀). 보는 팀의 범위만 "지금 속한 팀"에서 "속했던 팀"으로 넓혔다.
- **출처 검사**: 검사를 넓힌 쪽(우회)은 비노출을 강화하고, 좁힌 쪽(오탐)은 '메모'가 행동·물건을 뜻하는 쓰임에 한정했다. 출처로 말하는 표현은 새 강한 패턴이 따로 잡는다. 지시문은 바꾸지 않았다.
- **입력 정리**: 저장 전에 지우므로 이후 화면·모델 입력 모두에 적용된다. 줄바꿈과 탭은 남겨 회의록 서식이 깨지지 않는다.
- **운영 키 검사**: 지금 운영은 키가 있어 영향이 없다(11/12 배포 점검에서 실제 모델 응답 확인). 키를 지운 채 `AI_PROVIDER=openai`로 배포하면 서버가 시작하지 않는다. AI 없이 운영하려면 `AI_PROVIDER=none`으로 둔다.

### 남는 한계

- 출처 검사는 여전히 낱말·표현 패턴이다. 새 표현으로 돌려 말하면 놓칠 수 있고, 메모에 대해 묻는 대화에서 "메모에는 … 적혀 있어요" 같은 평범한 문장이 걸려 한 번 다시 쓰일 수 있다. 「AI만 참고」의 내용이 답에 반영되는 것 자체는 설계다.
- "N1" 보존은 일본어능력시험 맥락과 질문에 나온 낱말에 한정한 규칙이다. 그 밖의 맥락에서 실제 낱말인 N1~N30은 여전히 지워질 수 있다.
- 요청 시간 50초는 함수 제한 60초를 전제로 한다. 함수 제한을 바꾸면 `AI_REQUEST_BUDGET_MS`도 함께 바꾼다. 시간을 넘긴 질문은 실패로 기록되고 「다시 시도」할 수 있다.
- 팀에 공개한 메모는 작성자가 나가도 남는다(합의된 동작). 나간 작성자가 이를 거두려면 API로 철회·삭제하거나 다시 참여해야 한다. 나간 팀의 메모를 관리하는 화면은 없다.
- 혼자 쓰던 팀을 「나가기」만 하고 탈퇴하지 않으면 그 팀은 남는다(초대 코드로 돌아오면 팀장이 된다, §21).
