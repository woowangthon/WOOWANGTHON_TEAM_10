## 3. 실행과 검증

```bash
npm ci
cp .env.example .env.local        # DATABASE_URL, SESSION_SECRET(32자 이상) 채우기
npm run db:migrate
npm run dev                       # http://localhost:3000
```

- **고칠 때마다** `npm run check`(타입 검사 + 테스트)를 돌린다. 테스트는 실제 PostgreSQL을 쓰고, 그 DB의 **모든 표를 비운다**. 그래서 DB 이름에 `test`가 없으면 실행을 거부한다.
  기본값: `DATABASE_URL=postgres://mijuk:devpass@localhost/mijuk_test`
- 푸시하면 GitHub Actions(`.github/workflows/ci.yml`)가 타입 검사·마이그레이션·테스트·빌드를 돌린다.
- 배포본 점검: `npm run smoke -- --url=https://mijuk00.vercel.app` (시험 계정을 만들고 끝나면 탈퇴로 지운다). `/api/health`가 503이면 첫 단계에서 멈춘다.
- 프록시를 거치는 환경(Claude 클라우드 세션 등)에서는 `NODE_USE_ENV_PROXY=1`을 붙여 실행한다.
- 실제 모델 평가: `npm run eval:v2 -- --repeat=3` (`AI_PROVIDER=openai`와 키가 필요하다. 비용은 1회 약 $0.01~0.03)
- 새 마이그레이션(`db/migrations/00N_*.sql`)을 추가했다면 `src/lib/schema-version.ts`의 목록에도 추가한다(빠뜨리면 테스트가 실패한다). 운영 DB에는 **Vercel 운영 배포의 빌드 단계가 자동으로 적용**한다(`scripts/predeploy.ts`, 2026-11-11부터). 사람이 따로 돌리지 않는다.
- 새 스키마가 적용된 뒤 새 코드가 올라오기까지 잠깐은 이전 코드가 새 스키마로 돈다. 그래서 마이그레이션은 **이전 코드가 계속 동작하도록 열·표 추가 위주로** 쓴다. 지우거나 이름을 바꾸는 변경은 두 번의 배포로 나눈다.
- `main`에 병합되면 「배포 확인」 워크플로가 운영 배포본을 확인한다(배포 커밋, DB·마이그레이션, 로그인 경로). **빨간색이면 병합이 끝난 것이 아니다.** 직접 확인: `npm run deploy:check -- --url=https://mijuk00.vercel.app`

## 4. 깨면 안 되는 규칙

고치다가 아래와 충돌하면, 고치지 말고 충돌한다고 보고한다.

1. **「AI만 참고」 지식의 비노출**
   - 팀원에게 출처, 작성자, 원문 표현, 그리고 **그런 정보가 있다는 사실**을 드러내지 않는다.
   - 그 안에 담긴 누군가에 대한 평가·의견·걱정·의심은 **그런 의견이 있다는 사실도** 전하지 않는다(프롬프트 `2026-11-09.2`).
   - 일정·장소 같은 내용 반영은 정책상 허용한다(README §1).
2. **지식이 바뀔 때 답변 다시 쓰기**
   - 삭제·「AI만 참고」로 범위 좁히기: 그 지식이 AI에 **넘어간** 모든 답변을 다시 쓴다(이전 답변·대화 요약을 거쳐 퍼진 것 포함).
   - 철회·수정·AI 참고 끄기: AI가 반영했다고 **밝힌** 답변만 다시 쓴다.
   - 다시 쓸 때 "숨겼습니다" 같은 안내는 하지 않는다.
3. **팀 경계·권한**: 다른 팀의 자료는 어떤 경로로도 보이거나 AI에 넘어가면 안 된다. 메모는 작성자만 보고, 회의록 철회·삭제는 처음 쓴 사람과 팀장만 한다.
4. **테스트를 끄거나 지우거나 건너뛰어서 통과시키지 않는다.** 테스트는 `tests/` 아래 227개(2026-11-13 기준)이고, 핵심은 `access`·`visibility`·`chat`·`meetings`·`review-fixes`·`review2-fixes`다.
5. AI 호출과 DB 쓰기는 **서버 코드에서만** 한다. `NEXT_PUBLIC_` 변수에 비밀값을 넣지 않는다.
6. 키·DB 주소·세션 키는 저장소·채팅·문서에 넣지 않는다. 시연·평가 자료에는 가상 데이터만 쓴다.
7. 프롬프트(`src/lib/ai/prompts.ts`)를 바꾸면 버전 문자열을 올리고, 바뀐 이유를 `docs/평가_보고서.md`에 적는다. **검증용 평가 문항을 보고 프롬프트를 고쳤다면** 그 문항에 `dev: true`를 달고 검증 수치에서 뺀다(q12가 그 예).

## 5. 작업별 안내

세 작업은 **서로 다른 세션에서** 하는 것을 권한다. 특히 평가는 다른 작업의 결론을 보기 전에 한다.

### 5.1 버그 수정

- 이미 알려진 약점은 `docs/평가_보고서.md` §5(검증되지 않은 것)·§8(약한 점과 기술 부채)와 `docs/보안_점검.md`의 「남아 있는 한계」·「남는 한계」 절에 있다. 같은 내용을 새 발견으로 보고하지 않는다.
- 버그 하나마다 다음 순서로 한다.
  1. 실패하는 테스트로 버그를 재현한다.
  2. 고친다.
  3. `npm run check`가 통과하는지 확인한다.
  4. 바뀐 점을 `docs/보안_점검.md`에 날짜 절로 남긴다.
- 맡긴 사람이 직접 발견한 버그는 재현 단계와 함께 따로 받는다.

### 5.2 새로운 관점에서 평가

- **`docs/평가_보고서.md`의 결론과 해석은 먼저 읽지 않는다.** 서비스 주소와 README §1만 보고 판단한 뒤, 마지막에 비교한다.
- 관점 예시:
  - 처음 보는 심사위원: 3분 안에 무엇을 하는 서비스인지 알 수 있는가
  - 실제 대학생 팀원: 메모를 남길 동기가 있는가, 입력 수고는 어떤가
  - 경쟁 서비스(Notion AI, 일반 ChatGPT 프로젝트 등)와 비교한 차별점
  - 「AI만 참고」 정책이 사용자에게 "비밀 보장"으로 오해될 위험
- 결과는 「강점 / 약점 / 고칠 것(우선순위) / 근거」로 정리한다.
- 평가 자료(`eval/`)는 개발 쪽이 직접 만든 가상 자료이고, AI 채점자도 같은 계열 모델이다. 사람이 다시 채점한 것은 한 회차뿐이다(`docs/평가_보고서.md` §23). 이 한계를 감안해 수치를 읽는다.

### 5.3 UI 개선

- 화면 파일

  | 파일 | 화면 |
  | --- | --- |
  | `src/app/page.tsx` | 로그인·가입, 팀 목록 |
  | `src/app/account-access.tsx` | 이메일 없는 시작·코드 보관·재접속·탈퇴, 기존 계정 로그인 |
  | `src/app/teams/team-header.tsx` | 팀 화면 공통 머리 |
  | `src/app/memo-fab.tsx` | 옆 메뉴의 「메모하기」 버튼과 입력 창 |
  | `src/app/teams/[teamId]/page.tsx` | 팀 첫 화면, 프로젝트 목록 |
  | `src/app/teams/[teamId]/tasks/[taskId]/page.tsx` | 프로젝트 AI 대화 |
  | `src/app/teams/[teamId]/memos/page.tsx` | 메모 보기·정리·공유 |
  | `src/app/teams/[teamId]/meetings/page.tsx` | 회의록 |
  | `src/app/globals.css` | 공통 스타일 |
  | `src/app/api-client.ts` | 화면에서 API를 부르는 함수 |
  | `src/app/pane-picker.ts` | 가운데 목록 펼침·접힘(넓은 화면은 항상 펼침) |
  | `src/app/theme-toggle.tsx`, `public/theme-init.js` | 화면 테마 전환과 첫 그리기 전 적용 |

- 대상 사용자는 대학생 프로젝트 팀과 비전공 심사위원이다. 휴대폰 화면에서도 쓸 수 있어야 한다.
- 답변 하나에 약 10초가 걸리고 스트리밍은 쓰지 않는다. 근거 검증 전에 본문을 보여주지 않으려는 설계이므로 기다리는 동안의 표시가 중요하다.
- UI 문구에도 §4-1의 비노출 규칙이 적용된다. 예를 들어 「참고한 팀 지식」에 「AI만 참고」 지식이 보이면 안 된다.
- 바꾼 화면은 고치기 전·후 스크린샷으로 보여준다. 동작은 Playwright로 두 계정 흐름을 확인한다(`docs/평가_보고서.md` §4.2 참고).
- API 응답 형식을 바꿔야 한다면 서버 쪽 테스트도 함께 고친다.

## 6. 넘기지 않는 것

다음은 이 문서와 저장소에 없고, 넘겨서도 안 된다: `OPENAI_API_KEY`, 운영 `DATABASE_URL`(Neon), `SESSION_SECRET`, Vercel·Neon 계정.
실제 모델 평가나 배포가 필요하면, 작업자의 환경에 저장소 주인이 직접 등록한다.
