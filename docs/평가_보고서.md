## 0. 한 줄 요약

**AI 없이 돌아가는 뼈대는 완성됐고, 권한·확인·철회 같은 안전 규칙은 자동 테스트로 확인됐다. 그러나 제품의 핵심 가치인 "표현이 달라도 관련된 생각을 찾아 연결"은 AI를 연결해야 검증할 수 있고, 실제 사용자·실제 문제 사례·배포는 아직 하나도 없다.**

지금 제출한다면 "잘 설계된 메모 공유 도구"이지 "AI 조언자"는 아니다. 남은 12일의 우선순위는 분명하다: AI 연결 → 평가 데이터 → 배포 → 자기 팀 파일럿.

## 1. 무엇을 만들려 했나

원안의 목표: 팀원이 짧게 남긴 미완성 생각을 작성자 확인 후 팀 기억에 저장하고, 다른 팀원이 작업할 때 관련 생각을 찾아 **근거 있는 조언**으로 연결하는 작은 웹 서비스. 핵심은 ① AI 정리가 의미를 왜곡하지 않게 작성자가 확인하는 것, ② 모델이 근거를 지어내지 못하게 서버가 검증하는 것, ③ 철회·수정이 이후 조언에 즉시 반영되는 것이었다.

## 8. 코드·설계 품질 평가

### 잘 된 점
- 권한은 프롬프트가 아니라 **서버와 DB 제약**으로 강제한다 (팀 경계 외래키, 모든 조회 전 가입 확인, 타 팀 자료는 존재 여부도 숨김).
- 작성자가 확인한 **정확한 버전**이 해시로 고정되고, 확인하지 않은 정리는 공유될 수 없다.
- 모델에는 요청 한정 번호만 주고, 돌아온 근거·인용을 서버가 다시 검사한다. 모델이 무엇을 내놓든 검증을 통과한 것만 저장된다.
- 생성 중 변경(철회·작업 수정·탈퇴)을 확정 직전에 다시 확인하고, 잠금 순서를 고정해 교착을 막는다.
- 테스트가 가짜 DB가 아니라 **실제 PostgreSQL**로 돌고, 악의적·고장난 모델 출력을 직접 흉내 낸다.
- 비전문가가 실수하기 쉬운 지점(운영 DB 초기화, 설정 누락, 키 커밋)에 장치를 두었다.

### 약한 점과 기술 부채
- **키워드 검색이 단순하다.** 조사 몇 개를 떼는 수준이라 "실험"과 "실험적"은 찾지만 "측정 조건"과 "실험 환경"은 못 찾는다. 임베딩 검색을 붙여야 한다.
- **세션을 서버에서 취소할 수 없다.** 비밀번호 변경·강제 로그아웃이 없다.
- **요청 제한이 서버 메모리 기준**이라 서버가 여러 대면 따로 센다.
- **CSP가 인라인 스크립트를 허용**한다. 주입 방어는 React의 자동 이스케이프에 기댄다.
- **화면이 최소 수준**이다. 로딩 표시·확인 대화상자·오류 문구는 있으나 디자인·안내는 투박하다.
- **로그·모니터링이 없다.** 오류 종류만 콘솔에 남긴다. Vercel 로그에 의존하게 된다.
- **메모의 "AI 정리 허용"을 나중에 바꿀 수 없다.**
- 한국어 UI만 있다 (대회 범위에서는 문제 아님).
