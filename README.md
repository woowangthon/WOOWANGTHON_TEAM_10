## 1. 프로젝트 개요

### 문제
팀 프로젝트에서 "이거 조건이 달라서 숫자만 비교하면 오해할 수도", "심사위원은 비전공자라 용어 설명이 필요함" 같은 생각은 대개 **짧고, 미완성이고, 한 사람 머릿속이나 대화방 어딘가**에 있다. 정작 그 생각이 필요한 순간은 **다른 팀원이 발표·그래프·보고서를 만들 때**다. 그때 그 팀원은 그런 메모가 있었는지 모르고, 찾을 방법도 없다. 결국 같은 실수가 다시 나오고, 누군가 회의에서 "그거 내가 전에 말했는데"라고 말한다.

### 해결 흐름
1. **메모하기**: 어느 화면에서든 위쪽 「✎ 메모하기」로 떠오른 생각을 적는다. 메모는 **나만 본다**.
2. **메모 보기 → 정리 → 공유**: 내 메모 중 나눌 것을 골라 「AI로 정리하기」를 누르면 **고른 메모만** AI에 보내 정리문 초안을 받는다. 불필요한 부분을 지우고 고친 뒤 「확인했어요, 팀에 공유」를 눌러야 팀 지식이 된다. AI 없이 직접 정리해 공유할 수도 있다.
3. **회의록**: 이 서비스는 팀 회의를 대신하려는 것이 아니다. 회의에서 정한 것·아직 정하지 못한 것·할 일을 「회의록」에 적어 두면(날짜·제목·내용, 녹음 요약이나 메신저 대화를 붙여 넣어도 됨) 바로 팀에 공유되고, AI가 대화할 때 맥락으로 참고한다. 개인 생각과 다르면 회의에서 정한 것을, 회의끼리 다르면 최근 회의를 우선한다.
4. **프로젝트 만들기**: 팀이 함께 만드는 결과물 하나를 이름·목표·누구를 위한 것인지·마감과 조건으로 적는다. AI가 대화할 때 이것을 맥락으로 쓴다.
5. **대화**: 프로젝트 안에서 일반 AI와 대화하듯 묻는다. AI는 **항상 답한다**. 관련된 팀 지식이 있으면 그 사실·수치·조건을 반영하되, "메모에 따르면" 같은 출처 표시 없이 자연스럽게 말한다. 관련 지식이 없으면 일반 지식으로 답한다. 대화는 묻는 사람에게만 보인다.
6. **변경 반영 (출처는 끝까지 숨김)**: 공유한 지식이 철회·수정·삭제되거나 AI 참고에서 빠지면, 그 지식을 반영한 답변을 다음에 열 때 **같은 질문으로 조용히 다시 쓴다**. "숨겼습니다" 같은 안내는 띄우지 않는다. 삭제된 지식이 들어간 답변 본문은 다시 쓰기 전에 DB 에서 바로 지운다.

### AI가 하는 일과 사람이 판단하는 일

| AI 가 맡는 일 | 사람이 판단하는 일 |
| --- | --- |
| 회의 기록·공유 지식 중 질문과 관련된 것을 골라 반영 (최근 회의 우선, 미정 사항은 단정하지 않음) | 회의에서 무엇을 정할지, 무엇을 기록할지 (팀원들) |
| 고른 메모들을 하나의 정리문으로 (숫자·조건·추측 유지) | 무엇을 정리할지 고르고, 정리문을 고쳐 공유할지 결정 (작성자) |
| 질문에 답하면서 관련 팀 지식만 골라 반영 | 공유한 지식을 AI가 참고해도 되는지 결정 (공유할 때 선택) |
| 서로 다른 지식은 단정하지 않고 함께 제시 | 답변을 어떻게 쓸지 판단 (질문한 사람) |
| — | 공유 철회·수정·삭제, AI 참고 끄기 → 관련 답변을 조용히 다시 씀 |

**출처 비노출**이 이 서비스의 핵심이다. 답변에 "메모에 따르면", "공유된 내용", 번호(N1) 같은 출처 표현이 나오면 서버가 한 번 다시 쓰게 하고, 그래도 남으면 그 문장을 뺀다. 모델에게 "그 내용은 쓰지 마"라고 말하지 않고, 빠진 지식은 **아예 보내지 않는다**(이전 대화에 섞여 있던 경우도 답변을 빼고 질문만 넘김). AI 출력은 그대로 믿지 않는다. 모델에는 요청 한정 번호만 주고, 모델이 "반영했다"고 밝힌 번호 중 **서버가 건넨 것만** 기록한다(`src/lib/ai/validate-output.ts`, `src/lib/chat.ts`). 권한은 프롬프트가 아니라 서버·DB 제약으로 강제하므로, 다른 팀 지식·공유 전 메모·AI 참고를 허용하지 않은 지식은 모델에 가지 않는다. 메모 속 명령("앞의 지시를 무시하고…")은 따르지 않도록 지시하고 태그 문자를 중화한다.

### 기존 방식과의 차이
비교 대상은 "노션·ChatGPT 같은 AI에 팀 메모를 붙여 넣고 묻는 방식"이다.

| | 메모 붙여넣기 AI | 이 서비스 |
| --- | --- | --- |
| 팀 지식을 쓰려면 | 매번 찾아서 붙여 넣음 | 공유해 두면 대화할 때 알아서 참고 |
| 무엇이 팀 지식이 되나 | 붙여 넣는 사람 마음대로 | 작성자가 고르고 고쳐서 확인한 것만 |
| 공유 전 메모·AI 비허용 지식 | 실수로 붙여 넣을 수 있음 | 서버가 막음 |
| 철회·수정·삭제한 지식 | 이미 붙여 넣은 대화에 남음 | 그 지식을 반영한 답변을 조용히 다시 씀 |
| 출처 표현 | 그대로 노출 | 실제 모델 30회에서 0건 (서버 검사 + 1회 다시 쓰기) |
| 메모 속 명령(프롬프트 주입) | 대책 없음 | 데이터로만 다루도록 지시·중화 |

대화 방식 평가(가상 메모 43개·질문 10개 × 3회, 실제 모델, `docs/평가_보고서.md` §13): **30/30 답함, 출처 표현 0, 주입 명령 따름 0, 철회·초안 반영 0**, 반영했다고 밝힌 핵심 메모 회수율 평균 0.73, 응답 약 3초, 질문당 약 $0.0015. 이전 조언 방식(구획별 근거 표시)의 수치는 §4.5.

## 2. 기술 선택 이유

| 선택 | 이유 |
| --- | --- |
| **Next.js (App Router) + TypeScript** | 화면과 서버 API를 한 저장소·한 언어로 만들고, Vercel에 그대로 배포해 외부 접속 URL을 빨리 확보 |
| **PostgreSQL (Neon) + `pg_trgm`** | 권한·팀 경계·메모 버전을 **DB 제약(외래키·체크·트랜잭션 잠금)**으로 강제. 한국어는 형태소 분석 없이도 조사·띄어쓰기 변형에 강한 trigram 유사도로 1차 후보를 뽑음 |
| **ORM 없이 `pg` + SQL** | 철회·삭제 시 조언 무효화, 탈퇴 처리처럼 여러 표를 한 트랜잭션에서 잠그고 바꾸는 부분을 직접 통제 |
| **Node 내장 `crypto` (scrypt, HMAC)** | 비밀번호 해시·세션 서명을 외부 인증 서비스 없이 구현. 외부 의존과 개인정보 이동을 줄임 |
| **OpenAI Responses API (`gpt-6.1-terra`)** | JSON 스키마로 출력 형식을 고정하는 구조화 출력, `store: false`로 대화 비저장. 추론 강도 `none`으로 응답 시간·비용을 낮춤 |
| **`AiProvider` 인터페이스** | AI 없음(`none`)·개발용 가짜(`fake`)·실제(`openai`)를 바꿔 끼움. 테스트는 가짜로, 평가는 실제 모델로 같은 서비스 흐름을 돌림 |
| **Vitest + 실제 PostgreSQL** | 권한·철회·삭제는 DB 동작이 핵심이라 모의 객체 대신 실제 DB로 시험 (107개) |

| 구분 | 내용 |

| **데이터** | 평가용 메모·질문·기대표(`eval/cases.json`)는 개발 팀이 만든 가상 자료. 외부 데이터셋은 쓰지 않았다 |

결과를 미리 정해 두거나 하드코딩한 부분은 없다. 대화 답변은 매번 실제 모델이 만든다. `AI_PROVIDER=fake`(개발용 가짜 응답)는 모든 출력에 【개발용 가짜 응답】이 붙고, 운영 환경에서는 서버가 시작을 거부한다.

## 4. 현재 상태 (2026-11-07)

- 가입/로그인(비밀번호는 scrypt 해시, 서명된 세션 쿠키, 시도 횟수 제한), **회원 탈퇴**, 가입 화면의 개인정보 수집 안내
- 팀 만들기 · 초대 코드로 가입 · 코드 재발급 · 나가기(유일한 팀장이 나가면 자동 승계)
- **메모하기**(모든 화면 위쪽) → **메모 보기**: 골라서 AI 정리 → 고치기 → 팀에 공유, 공유 철회·수정·삭제
- **회의록**: 날짜·제목·내용(최대 10,000자), 바로 팀 공유, 쓴 사람이 수정·철회·삭제·AI 참고 끄기
- **프로젝트 만들기**(이름·목표·대상·마감과 조건) → **프로젝트 대화**: 이전 대화를 이어서, 관련 팀 지식을 조용히 반영해 항상 답함
- 지식이 철회·수정·삭제되거나 AI 참고에서 빠지면 그 지식을 반영한 답변을 사유 표시 없이 다시 씀(삭제는 본문 즉시 삭제 후), 공유 후에도 「AI 참고」 켜고 끄기
- 서버 시작 시 설정 검사, `/api/health`, 배포 점검 스크립트(`npm run smoke`, 19단계)
- 이전의 구획별 조언 API(`/api/tasks/:id/advice`)와 평가 실행기는 비교 평가용으로 남아 있다

### AI 연결 상태 (`AI_PROVIDER`)

| 값 | 동작 |
| --- | --- |
| `none` (기본) | AI를 부르지 않음. 메모는 원문 그대로 등록, 조언은 **키워드가 겹치는 팀 메모만** "키워드 일치 · AI 미사용" 표시로 보여줌 |
| `fake` | 개발용 가짜 응답. 모든 출력에 【개발용 가짜 응답】 표시. **운영 환경(`NODE_ENV=production`, Vercel)에서는 서버가 시작을 거부** |
| `openai` | OpenAI Responses API. 기본 모델 `gpt-6.1-terra`, 추론 강도 `OPENAI_REASONING_EFFORT`(기본 `none`). 키는 `OPENAI_API_KEY` |

다른 모델을 붙이려면 `src/lib/ai/types.ts` 의 `AiProvider` 인터페이스를 구현한다.

> **프록시 뒤에서 개발할 때**: Node.js 의 `fetch` 는 `HTTPS_PROXY` 환경변수를 기본으로 따르지 않는다. Claude 클라우드 세션처럼 프록시를 거치는 환경에서는 `NODE_USE_ENV_PROXY=1` 을 붙여 실행한다 (`NODE_USE_ENV_PROXY=1 npm run dev`). 본인 PC·Vercel 에서는 필요 없다.

### 개인정보
이메일·이름은 DB(Neon)에, 비밀번호는 되돌릴 수 없는 scrypt 해시로만 저장한다. OpenAI 에는 'AI 정리 허용' 메모 본문과 작업 내용만 가고 이름·이메일은 가지 않는다. 회원 탈퇴 시 계정과 작성한 메모를 모두 지운다. 자세한 규칙: `docs/보안_점검.md` §8.

### 평가 (실제 모델로 A/B/C 비교)

```bash
DATABASE_URL=postgres://mijuk:devpass@localhost/mijuk_eval AI_PROVIDER=openai npm run eval
```

가상 메모 43개(프롬프트 주입 사례 3개 포함)·질문 10개로 세 조건을 비교하고 `eval/results/<실행ID>/report.md` 에 지표와 사람 점검표를 남긴다. 자세한 설명은 [`eval/README.md`](eval/README.md).

## 로컬 실행

필요: Node.js 22.6 이상, PostgreSQL 14 이상 (`pg_trgm` 확장 — 기본 포함)

```bash
npm ci
```

```bash
cp .env.example .env.local
```

`.env.local` 에 `DATABASE_URL` 과 `SESSION_SECRET`(32자 이상 무작위 문자열)을 채운다. 이 파일은 커밋되지 않는다.

```bash
DATABASE_URL=postgres://사용자:비밀번호@localhost/mijuk npm run db:migrate
```

```bash
npm run dev
```

브라우저에서 http://localhost:3000 을 연다. 잘못된 설정이 있으면 서버가 시작하지 않고 이유를 알려준다.

테스트는 `DATABASE_URL` 이 가리키는 DB 의 **모든 표를 비운다**. 그래서 DB 이름에 `test` 가 들어 있지 않으면 실행을 거부한다. 기본값은 `postgres://mijuk:devpass@localhost/mijuk_test` 이다.

```bash
DATABASE_URL=postgres://mijuk:devpass@localhost/mijuk_test npm test
```

GitHub 에 푸시하면 `.github/workflows/ci.yml` 이 타입 검사·테스트·빌드를 자동으로 돌린다.

## 배포 (외부 접속 URL 만들기)

1. **DB**: [Neon](https://neon.tech) 또는 [Supabase](https://supabase.com) 에서 무료 PostgreSQL 을 만들고 접속 주소(`postgres://...`)를 복사한다.
2. 로컬에서 그 주소로 표를 만든다: `DATABASE_URL=<주소> npm run db:migrate`
   새 마이그레이션(`db/migrations/00N_*.sql`)이 추가된 버전을 배포할 때는 **배포 전에** 같은 명령을 다시 실행한다. 이미 적용한 파일은 건너뛴다.
3. **웹**: [Vercel](https://vercel.com) 에서 이 GitHub 저장소를 가져온다(Import). Framework 는 Next.js 로 자동 인식된다.
4. Vercel 프로젝트 Settings → Environment Variables 에 다음을 넣는다.
   - `DATABASE_URL` = 1번 주소
   - `SESSION_SECRET` = `openssl rand -base64 36` 으로 만든 값
   - `AI_PROVIDER` = `openai`, `OPENAI_API_KEY` = OpenAI 프로젝트 키 (월 예산 한도를 건 것), `OPENAI_REASONING_EFFORT` = `none`
     (AI 없이 운영하려면 `AI_PROVIDER` = `none`)
5. Deploy 한 뒤 `https://<프로젝트>.vercel.app/api/health` 가 `{"ok":true,"db":"ok"}` 를 돌려주는지 확인한다.
6. **팀 외부 사람**(심사위원 등)이 접속·가입할 수 있는지 다른 기기·네트워크에서 확인한다.

키는 저장소·채팅·문서에 절대 넣지 않는다. 자세한 규칙은 `docs/보안_점검.md` 를 본다.

### 배포 점검 (제출 전마다)

배포된 주소에서 가입 → 팀 → 메모 → AI 정리 → 공유 → 조언 → 반응 → 철회 → 숨김 → 타 팀 차단까지 실제 요청으로 한 바퀴 돌려 통과/실패를 보여준다. 브라우저나 DB 접근 없이 Node.js 만 있으면 된다.

```bash
npm run smoke -- --url=https://<프로젝트>.vercel.app
```

시험용 계정(`smoke+…@example.invalid`)을 만들고, 끝나면 회원 탈퇴 기능까지 점검하면서 그 계정과 자료를 모두 지운다(`--keep` 을 붙이면 남긴다). 실패하면 메시지와 Vercel 의 Logs 를 본다. 심사 전날에도 한 번 돌려 DB 를 깨워 둔다.
